# Demo Mode

`pnpm db:seed` (or the first "Continue with demo workspace" login) generates:

- 1 demo organization ("Acme Corp (Demo)"), clearly flagged `demo: true`
- 3 synthetic repositories: `acme/web-app` (Next.js/pnpm), `acme/api-service`
  (Node/npm), `acme/data-pipeline` (Python/pip) — each with `demo: true`
- ~30 days of commit + CI run history per repository (~107 workflow runs
  total), ~18% of which fail
- Realistic **hand-crafted log excerpts** for each failure category
  (`src/lib/demo/log-fixtures.ts`) run through the **real** deterministic AI
  analyzer during seeding — the persisted root-cause analyses are genuine
  output of `local-analyzer.ts`, not canned JSON
- Test results including designed-flaky tests (alternating pass/fail) whose
  `FlakyTestScore` rows are computed by the same `computeFlakyScore()`
  function the dashboard uses — not seeded numbers
- CI Optimizer recommendations generated by running the real
  `analyzeWorkflowYaml()` static analyzer against realistic (deliberately
  uncached) GitHub Actions YAML stored on each repo's `Workflow.definition`
- Deployments (including a couple of rollbacks) and pull requests with a
  lightweight, computed (not fabricated) risk summary

Demo data is never mixed with real connected-repository data — every demo
row traces back to `Organization.demo = true` / `Repository.demo = true`,
and the UI does not currently render a "demo" badge on every row (a
follow-up improvement) but the seed function refuses to run twice
(`ensureDemoData()` checks for an existing demo org first).

## Why this matters

The "No Fake Functionality" rule in the project brief this was built from
says: don't hardcode AI responses, don't create UI controls for
functionality that doesn't exist. Demo mode honors that by construction —
every number on the dashboard is a real query result against real (if
synthetic) rows, and every AI analysis shown was actually produced by the
analysis engine, not authored by hand to look plausible.
